# Operations

How to see that the platform is healthy, and what to do when it is not. Runbooks have the steps;
this page says where to look.

## Is it healthy?

| Check | Healthy looks like |
| --- | --- |
| `GET /readyz` on each control-plane replica | `200 {"status":"ready"}` (503 when the database is unreachable) |
| Dashboard, Gateways page | exactly one MASTER, both gateways on the same config version, no split-brain banner |
| Dashboard, Overview | warm pool near its target, free addresses above the reserve, no failed jobs |
| `ipo_gateway_masters` | 1 |
| Prometheus alerts | none firing |

## Metrics

Exported by the control plane at `/metrics` (computed from the database at scrape time, so each
replica reports the truth) and by each agent on `127.0.0.1:9100`.

| Metric | Type | Meaning |
| --- | --- | --- |
| `ipo_ip_addresses{state}` | gauge | addresses by lease state |
| `ipo_pool_size`, `ipo_pool_target` | gauge | warm VMs ready, and the target |
| `ipo_teams{state}` | gauge | teams by state |
| `ipo_config_live_version{gateway}` | gauge | config version each gateway runs |
| `ipo_gateway_masters` | gauge | gateways whose fresh heartbeat says MASTER; 1 is right, 2 is a split brain |
| `ipo_split_brain_total` | counter | times two MASTERs were seen |
| `ipo_provision_duration_seconds{path}` | histogram | registration request to active team, warm vs cold |
| `ipo_saga_step_duration_seconds{step}`, `ipo_saga_jobs_total{kind,outcome}` | histogram, counter | saga timing and outcomes |
| `ipo_reconciler_repairs_total{rule}` | counter | drift repaired, by rule |
| `ipo_api_request_duration_seconds{method,route,status}` | histogram | API latency |
| `ipo_team_requests_5m{team,class}`, `ipo_team_latency_ms_5m{team}` | gauge | each routed team's traffic over five minutes |
| `ipo_agent_config_version`, `_config_applied_total`, `_config_rejected_total{reason}`, `_rollbacks_total` | gauge, counters | the agent's config pipeline |
| `ipo_agent_vrrp_master`, `_vrrp_transitions_total` | gauge, counter | this gateway's VRRP state |
| `ipo_agent_reload_duration_seconds` | histogram | time to converge a config |

## Dashboards

Generated by `observability/build_dashboards.py` (tests keep them in sync with the metric names)
and provisioned into Grafana: **IPO Overview**, **IPO Gateways** (including the split-brain
panels), **IPO IPAM**, **IPO Provisioning**, **IPO Team Traffic** (a `$team` variable). The
dashboard's *Metrics* page embeds panels from them for staff; team logins never see Grafana,
because a panel URL can be edited to show another team.

## Alerts

Defined in `observability/alerts.yml` (checked with `promtool`); each links to a section of the
[alert runbook](../runbooks/alerts.md).

| Alert | Fires when | Severity |
| --- | --- | --- |
| `IPOGatewaySplitBrain` | two gateways report MASTER (5 s) | page |
| `IPONoGatewayMaster` | no gateway is MASTER (15 s) | page |
| `IPOGatewayFlapping` | more than 3 VRRP transitions in 2 minutes | page |
| `IPOGatewayVersionSkew` | gateways run different config versions (1 m) | page |
| `IPOConfigSignatureRejected` | an agent refused a bad signature | page |
| `IPOConfigRolledBack` | an agent rolled a config back | warn |
| `IPOWarmPoolLow` | pool under half its target (2 m) | warn |
| `IPOFreeAddressesLow` | fewer than 2 free addresses (2 m) | warn |
| `IPOSagaJobsFailing` | registration or teardown jobs failing or compensated | warn |
| `IPOReconcilerRepairing` | the reconciler repaired drift | warn |
| `IPOProvisioningSlow` | p95 registration time over 60 s (5 m) | warn |

## Routine tasks

| Task | How |
| --- | --- |
| Register a team | dashboard Teams, or `POST /v1/teams` with an `Idempotency-Key` (operator) |
| Give a team a login | `POST /v1/teams/{id}/users` (admin); the team sees only its own page |
| Extend or end a team | `POST /v1/teams/{id}/extend {seconds}`; `DELETE /v1/teams/{id}` |
| Resize the pool or TTLs | `PATCH /v1/settings` (admin), live |
| Fail over deliberately | dashboard Gateways, or `POST /v1/gateways/failover` ([runbook](../runbooks/manual-failover.md)) |
| Roll back a bad config | `POST /v1/config/rollback {"version": N}` (re-issued under a new number); `{"version": null}` unpins |
| Inspect history | `GET /v1/audit` (also reports whether the chain is intact); `GET /v1/config/versions` |
| Rotate certificates | automatic; `playbooks/rotate_certs.yml` to force ([runbook](../runbooks/rotate-certs.md)) |
| Promote the replica | [runbook](../runbooks/promote-replica.md) |
| Rebuild or restore | [rebuild](../runbooks/rebuild-from-zero.md), [restore](../runbooks/restore-backup.md) |

## Capacity

The sandbox range holds 100 addresses and the project allows 50 instances; see
[system architecture](../architecture/system-architecture.md#capacity-and-limits). Watch
`ipo_ip_addresses{state="free"}` and the project's instance quota in the cloud dashboard.
