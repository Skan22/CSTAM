# IPO dashboard

Admin UI for the control plane: overview, teams, gateways, IPAM, audit log and runtime settings.
Vite + React 19 + TypeScript + Tailwind 4. API types are generated from `docs/api/openapi.json`.

```
npm install
npm run dev          # http://127.0.0.1:5173, proxies /v1 to $IPO_API (default http://127.0.0.1:8000)
npm run typecheck && npm test
npm run build        # static files in dist/
npm run gen:api      # regenerate src/api/schema.d.ts after the API changes
```

To try it without OpenStack, start the control plane with `IPO_CLOUD=fake IPO_MIGRATE=1` and an
`IPO_ADMIN_EMAIL` / `IPO_ADMIN_PASSWORD` pair, then sign in with those.

## How it works

- **Same origin.** The app calls relative URLs, so production serves `dist/` and `/v1` from one
  reverse proxy (no CORS). In development the Vite proxy does the same.
- **Session.** `POST /v1/auth/login` gives a 15-minute token, kept in `sessionStorage`. The
  credentials are kept in memory only, so on a 401 the client logs in again once, retries the
  request, and otherwise returns to the login form.
- **Live updates.** One `EventSource` on `/v1/events` (token in `?access_token=`) is shared by every
  page. The server does not replay events, so pages refetch after a reconnect and also poll slowly
  as a safety net. The header badge shows the connection state.
- **Roles.** Navigation and buttons are hidden by role (`viewer` < `operator` < `admin`). That is
  convenience only; the API enforces the roles.
- **Destructive actions** (tear down, extend, fail over, roll back) always open a confirmation that
  lists what will change.

## Pages

Staff (viewer and up): Overview, Teams, Gateways, Traffic, Metrics, IPAM. Admin: Audit, Settings.

- **Traffic** reads `/v1/traffic`: per-team requests, status classes, bytes and latency from the
  gateway agents' Traefik access-log reports. Only hosts that have a route are counted, and no
  client addresses or query strings are stored.
- **Metrics** embeds Grafana panels (`/d-solo/...`) when the control plane has `IPO_GRAFANA_URL`.
  The panel list is generated by `observability/build_dashboards.py` into `src/generated/panels.json`
  and a control-plane test fails if it drifts from the dashboards. In production the URL is the
  path `/grafana`: the control plane's front (Caddy, `ansible/roles/control_plane`) serves the
  dashboard, `/v1` and Grafana on one origin, so the browser frames panels with Grafana's ordinary
  login cookie (`allow_embedding = true`, `SameSite=Lax`, `Secure`) and the front allows framing by
  that origin only. Staff only: a Grafana panel can be re-pointed at another team with a URL edit,
  so it is never shown to team accounts. `tests/deploy/test_grafana.py` checks all of this against
  a real Grafana 13 behind the real front; `docs/reports/grafana-embed.png` is the rendered result.

## Team accounts

An admin creates a login for a team (`POST /v1/teams/{id}/users`). That login has the `team` role,
which is not on the viewer < operator < admin ladder. It signs in to a single page that shows the
team's own host, state, expiry, traffic and recent requests, fed by `/v1/me*` and a filtered event
stream (`/v1/me/events`) that carries nothing about other teams, gateways or addresses. Every staff
route answers 403 to it, and the SPA only hides what the API already refuses.

## Not built

- **IPAM history** is read from the audit log (admin only); there is no per-address history API.
- Panels have been rendered with no Prometheus behind them (so they read "No data"); the queries
  themselves are checked against the metric names the code exports, not against live data.
